## Быстрый запуск готового образа

Создайте `docker-compose.yml` по [готовому примеру](docs/INSTRUCTION.md#docker-start).
В нём подключены `./downloads` и постоянный том `migration-data`; доступ
ограничен `localhost`. Затем выполните:

```bash
docker compose pull
docker compose up -d
```

Откройте <http://localhost:8000>. Для локального HTTP пример задаёт
`ONPREM_ALLOW_INSECURE_HTTP=1`: токены между браузером и утилитой не шифруются.
Для доступа с других компьютеров используйте HTTPS и авторизацию по
[инструкции](docs/INSTRUCTION.md#docker-start).
Справка по кнопке **«?»** содержит `docs/INSTRUCTION.md` и `docs/ONPREM.md`.

- **Перенос между SaaS-Дисками:** заполните форму и запустите выбранный режим.
  Ресурсы публикуются и сохраняются в папку с email источника на Диске получателя.
- **Сохранить локально:** выберите личный или общий Диск и укажите источник.
  Файлы скачиваются без публикации на машину утилиты.
- **Список источников для локального сохранения и On-premises:** выберите
  **«Список дисков из CSV»**, заполните шаблон и выполните **Dry Run**.
  В одном CSV — до **1000 строк с дисками**, без учёта заголовка.
  Client ID и секрет сервисного приложения дают доступ по email каждой строки;
  `ORGID` общий для списка. Необязательный `ADMIN_TOKEN` с правом
  `directory:read_users` проверяет организацию и активность сотрудника.
  Автоматической разблокировки в этих режимах нет.
  Максимум **четыре источника** работают одновременно во всей утилите,
  по одному файлу на источник. Ошибочный источник можно исключить или проверить
  повторно. [Требования по режимам](docs/INSTRUCTION.md#saas-access-modes).
- **«Несколько дисков» между SaaS-Дисками:** прежний шаблон принимает до 25
  пар, одновременно идут 5 переносов. Назначение — личный или общий Диск.

Галочка **«Автоматически повторять при ошибках»** по умолчанию включена во всех
режимах и списках CSV. Её можно менять во время работы без нового Dry Run.
Без галочки после первой ошибки файл пропускается с записью причины в журнал;
обработка остальных продолжается. [Подробнее о повторах](docs/INSTRUCTION.md#automatic-retries).

## SaaS → On-premises

Личный SaaS-Диск переносится на существующий общий Диск On-premises в папку
`/<SaaS email>` в корне общего диска, под исходными именами. В списке можно
добавить общие SaaS-диски: их папка — `/<название> (<ID>)`.
Права сотрудников, версии и исходные серверные даты не переносятся.

Утилита скачивает файл во временный кеш, проверяет размер и MD5, загружает
в On-premises и проверяет результат. Машине утилиты нужны доступ к обоим
сервисам и свободное место. По умолчанию бюджет кеша — **20 Гб**, резерв
свободного места — **1 Гб**. Пример настройки **100 Гб + 2 Гб** —
в [руководстве](docs/ONPREM.md#onprem-admin).

1. Подготовьте [доступы SaaS](docs/ONPREM.md#onprem-source-access) и
   [On-premises](docs/ONPREM.md#onprem-destination-access).
2. Нажмите **«Dry Run»**, дождитесь полного плана, проверьте пути и объём,
   затем нажмите **«Начать перенос»**.
3. Проверьте результаты всех файлов, сохраните отчёт и журнал CSV.
   При сбое используйте [таблицу ошибок](docs/ONPREM.md#onprem-errors).

Личные источники публикуются; ссылки сохраняются после переноса и остановки.
Общие SaaS-диски скачиваются с авторизацией, без публикации.
**«Перенесено»** означает, что размер и MD5 файла проверены.
**«Остановить полностью»** отменяет локальные действия и освобождает очередь
и пути. Уже принятая On-premises операция может продолжаться: API не даёт её
отменить. При ошибке передачи кеш сохраняется.
**«Проверить и повторить»** у файла проверяет диск и повторяет
загрузку из кеша. [Все кнопки](docs/ONPREM.md#onprem-buttons).

## Где хранятся данные

| Данные | Место в стандартном Compose |
|---|---|
| Локальная копия личного Диска | `./downloads/<email>/…` на машине запуска |
| Локальная копия общего Диска | Один источник: `./downloads/shared/<метка>/…`; список: `./downloads/<название> (<ID>)/…` |
| Планы и очередь списков | Том `migration-data`, `/var/lib/disk-copy/source-batches.db` |
| Журналы SaaS-переносов и локального сохранения | Том `migration-data`, `/var/lib/disk-copy/journals/history.db` |
| Задания, журнал и временный кеш SaaS → On-premises | Том `migration-data`, `/var/lib/disk-copy` в контейнере |

История сохраняется после перезапуска; журналы можно выгрузить в CSV.
Незавершённые SaaS-переносы и одиночные локальные сохранения помечаются как
прерванные. Для продолжения задания On-premises или списка источников
введите доступы заново: секреты хранятся только в памяти.
При обновлении сохраняйте `./downloads`, том `migration-data` и настройки.
Не выполняйте `docker compose down -v`: он удалит историю и кеш.
Схема базы On-premises — **8**; для отката нужны предыдущий образ и резервная
копия до обновления. [Порядок обновления](docs/UPDATE.md).

## Запуск из исходников

Для локального HTTP используйте override разработки:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build -d
```

Он разрешает HTTP для локального запуска. Ограничьте порт приложения
`127.0.0.1:8000:8000` либо firewall. Для HTTPS см.
[руководство администратора](docs/ONPREM.md#onprem-admin).

Без Docker:

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Основные файлы: `app/disk_copy.py` — SaaS и локальное сохранение;
`app/migration/` — SaaS → On-premises; `app/main.py` — API;
`app/static/` — интерфейс.
