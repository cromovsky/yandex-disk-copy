# Yandex Disk Copy — перенос и сохранение файлов

[![Docker v2](https://img.shields.io/docker/v/cromovsky/yandex-disk-copy-v2?logo=docker&label=docker%20v2&color=0f7ff0)](https://hub.docker.com/r/cromovsky/yandex-disk-copy-v2)
[![Docker v1](https://img.shields.io/docker/v/cromovsky/yandex-disk-copy?logo=docker&label=docker%20v1)](https://hub.docker.com/r/cromovsky/yandex-disk-copy)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
![Platforms](https://img.shields.io/badge/arch-amd64%20%7C%20arm64-blue)

Утилита с веб-интерфейсом для администраторов Яндекс 360. Переносит файлы
между Дисками сотрудников и сохраняет копии на машине, где запущена.
Для доступа к облачным Дискам использует сервисное приложение, поэтому пароли
сотрудников не нужны.

| Режим | Откуда и куда |
|---|---|
| Одна организация | С облачного Диска сотрудника на личный или общий Диск той же организации |
| Между организациями | С облачного Диска сотрудника на личный или общий Диск другой организации |
| Сохранить локально | С личных и общих облачных Дисков в каталог на машине запуска |
| SaaS → On-premises | С личного SaaS-Диска на личный или общий Диск On-premises. Общий SaaS-Диск можно перенести на общий Диск On-premises по CSV |

Режим «Сохранить локально» скачивает файлы. Загрузки локальных папок
в облачные аккаунты в этой версии нет.

Подробности: [доступы](docs/INSTRUCTION.md#saas-access),
[перенос и локальное сохранение](docs/INSTRUCTION.md),
[история и CSV](docs/INSTRUCTION.md#saas-journal),
[SaaS → On-premises](docs/ONPREM.md) и [обновление](docs/UPDATE.md).

## Что нового в 3.4.0

- На личный Диск On-premises можно перенести один файл, папку или весь Диск сотрудника SaaS. Для нескольких сотрудников загрузите CSV с парами «источник → получатель». Перед запуском проверьте UID получателя и итоговые пути. [Один получатель](docs/ONPREM.md#onprem-personal) · [Список пар](docs/ONPREM.md#onprem-personal-list)
- Для нового переноса на общий Диск On-premises укажите email сотрудника с правами чтения и записи. Сервисное приложение получает временный токен от его имени. [Настройка доступа](docs/ONPREM_ACCESS.md#onprem-destination-access)
- В одиночном задании SaaS → On-premises кнопка **«Выбрать на Диске…»** позволяет найти исходный файл или папку. Для CSV с личными Дисками в плане видны ошибки по строкам. Каждую строку можно проверить повторно или исключить.
- Во всех режимах очередь переходит к следующему файлу без прежней паузы в 20 секунд. При переносе личного Диска из SaaS в On-premises утилита повторяет публикацию файла или папки, если SaaS вернул HTTP 403 или 423 и автоматические повторы включены. После третьего отказа она записывает пропуск в журнал и продолжает перенос остальных объектов. [Повторы и журнал](docs/ONPREM.md#onprem-recovery)

## Быстрый запуск готового образа

Для новой установки сохраните [готовый файл Compose](docker-compose.hub.yml) под именем `docker-compose.yml` в каталоге установки. Он открывает интерфейс на `localhost`, сохраняет скачанные файлы в `./downloads`, а историю и кеш — в томе `migration-data`. Если утилита уже установлена, следуйте [инструкции по обновлению](docs/UPDATE.md).

Запустите утилиту из каталога установки.

```bash
docker compose pull
docker compose up -d --no-build
```

Откройте <http://localhost:8000>. Для локального HTTP пример задаёт
`ONPREM_ALLOW_INSECURE_HTTP=1`: токены между браузером и утилитой не шифруются.
Для доступа с других компьютеров используйте HTTPS и авторизацию по
[инструкции](docs/INSTRUCTION.md#docker-start).
Справка по кнопке **«?»** открывает инструкции по каждому режиму. Регистрация сервисных приложений и получение токенов описаны во вкладке **«Токены и права»**.

- **Перенос между SaaS-Дисками:** заполните форму и запустите выбранный режим.
  Ресурсы публикуются и сохраняются в папку с email источника на Диске получателя.
- **Сохранить локально:** выберите личный или общий Диск и укажите источник.
  Файлы скачиваются без публикации на машину утилиты.
- **Список источников для локального сохранения и On-premises:** выберите
  **«Список дисков из CSV»**, заполните шаблон и выполните **Dry Run**.
  В одном CSV — до **1000 строк с дисками**, без учёта заголовка.
  Client ID и секрет сервисного приложения дают доступ по email каждой строки;
  `ORGID` общий для списка. Необязательный `ADMIN_TOKEN` с правом
  `directory:read_users` проверяет организацию и активность сотрудника.
  Автоматической разблокировки в этих режимах нет.
  Локальное сохранение и SaaS → On-premises делят **четыре слота источников**.
  В каждом источнике файлы обрабатываются последовательно.
  Ошибочный источник можно исключить или проверить повторно.
  [Требования по режимам](docs/INSTRUCTION.md#saas-access-modes).
- **«Несколько дисков» между SaaS-Дисками:** прежний шаблон принимает до 25
  пар, одновременно идут 5 переносов. Назначение — личный или общий Диск.

В SaaS → On-premises, включая списки CSV, и локальном сохранении по CSV
после полного Dry Run по умолчанию выбраны все файлы и папки. Галочка папки меняет выбор
всего её содержимого; выбор вложенного файла включает нужные родительские папки.
Менять выбор можно до первого запуска, без нового Dry Run; он сохраняется
после обновления страницы и перезапуска контейнера. Исключённые объекты
не попадают в очередь, не считаются ошибками и не повторяются.
Без выбранных объектов запуск недоступен.

Галочка **«Автоматически повторять при ошибках»** по умолчанию включена во всех
режимах и списках CSV. Её можно менять во время работы без нового Dry Run.

## SaaS → On-premises

Личный SaaS-Диск переносится на существующий общий Диск On-premises в папку
`/<SaaS email>` в корне общего диска, под исходными именами. В списке можно
добавить общие SaaS-диски: их папка — `/<название> (<ID>)`.
Для доступа к общему Диску укажите email сотрудника с правами
чтения и записи. Сервисное приложение On-premises выдаёт и обновляет его
временный токен. Email оператора и метку общего Диска указывают один раз
для всего списка CSV. Готовый токен сотрудника используется при продолжении
старого задания, созданного с этим способом входа.
Права сотрудников, версии и исходные серверные даты не переносятся.

Для переноса на личный Диск On-premises укажите полный email получателя. Для одиночного задания подойдёт и числовой UID. Сервисное приложение получает временный токен сотрудника. Dry Run сохраняет UID владельца из ответа Диска. При долгом
переносе утилита обновляет токен и сверяет UID с планом. Файлы сохраняют исходные пути.
Для списка пар скачайте CSV-шаблон `source_email,path,destination_email,destination_folder`.
Пустые `path` и `destination_folder` означают перенос всего Диска в корень Диска получателя. [Как заполнить CSV](docs/ONPREM.md#onprem-personal-list).

Утилита скачивает файл во временный кеш, проверяет размер и MD5, загружает
в On-premises и проверяет результат. Машине утилиты нужны доступ к обоим
сервисам и свободное место. По умолчанию бюджет кеша — **20 Гб**, резерв
свободного места — **1 Гб**. Пример настройки **100 Гб + 2 Гб** —
в [руководстве](docs/ONPREM.md#onprem-admin).

1. Подготовьте [доступ к источнику SaaS](docs/ONPREM_ACCESS.md#onprem-source-access) и доступ к назначению в On-premises — [личному](docs/ONPREM_ACCESS.md#onprem-personal-access) или [общему Диску](docs/ONPREM_ACCESS.md#onprem-destination-access).
2. Нажмите **«Проверить план»** или **«Dry Run»** в зависимости от режима. Дождитесь полного плана, проверьте пути и объём,
   снимите галочки с ненужных файлов и папок, затем нажмите **«Начать перенос»**.
3. Проверьте результаты всех файлов, сохраните отчёт и журнал CSV.
   При сбое используйте [таблицу ошибок](docs/ONPREM.md#onprem-errors).

Личные источники публикуются; ссылки сохраняются после переноса и остановки.
Общие SaaS-диски скачиваются с авторизацией, без публикации.
**«Перенесено»** означает, что размер и MD5 файла проверены.
**«Остановить полностью»** отменяет локальные действия и освобождает очередь
и пути. Уже принятая On-premises операция может продолжаться: API не даёт её
отменить. При ошибке передачи кеш сохраняется.
**«Проверить и повторить»** у файла проверяет диск и повторяет
загрузку из кеша. [Все кнопки](docs/ONPREM.md#onprem-buttons).

## Где хранятся данные

| Данные | Место в стандартном Compose |
|---|---|
| Локальная копия личного Диска | `./downloads/<email>/…` на машине запуска |
| Локальная копия общего Диска | Один источник: `./downloads/shared/<метка>/…`; список: `./downloads/<название> (<ID>)/…` |
| Планы и очередь списков | Том `migration-data`, `/var/lib/disk-copy/source-batches.db` |
| Журналы SaaS-переносов и локального сохранения | Том `migration-data`, `/var/lib/disk-copy/journals/history.db` |
| Задания, журнал и временный кеш SaaS → On-premises | Том `migration-data`, `/var/lib/disk-copy` в контейнере |

История сохраняется после перезапуска; журналы можно выгрузить в CSV.
Незавершённые SaaS-переносы и одиночные локальные сохранения помечаются как
прерванные. Для продолжения задания On-premises или списка источников
введите доступы заново: секреты хранятся только в памяти.
При обновлении сохраняйте `./downloads`, том `migration-data` и настройки.
Не выполняйте `docker compose down -v`: он удалит историю и кеш.
Схема базы On-premises в 3.4.0 — **11**; для отката нужны предыдущий образ и резервная
копия до обновления. [Порядок обновления](docs/UPDATE.md).

## Запуск из исходников

Команды ниже собирают образ из исходников. Если установка уже работает,
сначала выполните [подготовку к обновлению](docs/UPDATE.md#перед-обновлением).
Для локального HTTP перед запуском замените привязку порта в
`docker-compose.yml` на `"127.0.0.1:8000:8000"`. Затем подключите
`docker-compose.dev.yml`, который разрешает HTTP:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build -d
```

Для HTTPS см.
[руководство администратора](docs/ONPREM.md#onprem-admin).

Без Docker, в окружении с Python 3.12:

```bash
python -m pip install -r requirements.txt
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Основные файлы: `app/disk_copy.py` — SaaS и локальное сохранение;
`app/migration/` — SaaS → On-premises; `app/main.py` — API;
`app/source_batches/` — списки источников; `app/static/` — интерфейс.
