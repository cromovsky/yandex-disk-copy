<details class="help-section" id="onprem-guide" markdown="1">
<summary>SaaS → On-premises — перенос на личные и общие Диски</summary>

<details class="help-chapter" id="onprem-requirements" markdown="1">
<summary>1. Какие доступы нужны для SaaS и On-premises</summary>

Откройте вкладку **«SaaS → On-premises»**. Для одного источника или всего списка CSV заполните два раздела формы. Если утилита запрашивает ключ доступа к режиму, получите `ONPREM_ADMIN_TOKEN` у её администратора.

| Раздел формы | Что подготовить |
|---|---|
| **Доступ к SaaS** | ID организации источника (ORGID), Client ID и Client secret зарегистрированного в ней сервисного приложения. Право `cloud_api:disk.read` нужно для чтения, `cloud_api:disk.write` — для публикации личного источника. При необходимости добавьте ADMIN_TOKEN с правом `directory:read_users`, чтобы проверить, что сотрудник входит в организацию и его учётная запись активна. [Доступы источника SaaS](ONPREM_ACCESS.md#onprem-source-access) |
| **Доступ к On-premises** | Адрес Disk API вида `https://cloud-api.<домен>/v1/disk`, Client ID и Client secret сервисного приложения `DISK_MIGRATION`, токен владельца организации On-premises. Приложению нужны права `cloud_api:disk.read`, `cloud_api:disk.write` и `cloud_api:disk.info`. [Регистрация приложения и получение токена владельца](ONPREM_ACCESS.md#onprem-personal-access) |
| **Личный Диск** | Полный email получателя On-premises. Для одиночного переноса подходит также числовой UID. Утилита получает временный токен сотрудника и проверяет его UID. |
| **Общий диск** | Полный email сотрудника On-premises с правом читать и записывать файлы. Подготовьте ссылку на корень существующего общего Диска или метку из его адреса `…/vd/<метка>/disk`. [Права сотрудника и метка общего Диска](ONPREM_ACCESS.md#onprem-destination-access) |

Одиночный источник — личный Диск SaaS. Чтобы перенести общий Диск SaaS, используйте список CSV и общий Диск назначения. Утилита копирует файлы и папки через временный кеш на своей машине. Права доступа, версии и исходные серверные даты не переносятся. Исходные файлы остаются на месте.

Оба образа **3.4.0** поддерживают перенос на личные и общие Диски по одному заданию или списком CSV. Для задания, созданного в 3.3.0 с готовым токеном сотрудника, по-прежнему нужен токен того же владельца. [Продолжить задание с готовым токеном](ONPREM_ACCESS.md#onprem-destination-access) · [Настроить сеть и кеш](#onprem-admin)

</details>

<details class="help-chapter" id="onprem-personal" markdown="1">
<summary>2. Один источник → личный Диск сотрудника On-premises</summary>

1. В поле **«Источники»** выберите **«Один диск»**, в поле **«Куда переносим»** — **«Личный Диск»**. Заполните **«Доступ к SaaS»** и **«Доступ к On-premises»**. [Какие доступы нужны](#onprem-requirements)
2. Введите **«Email владельца личного Диска SaaS»**. В поле **«Исходный путь»** укажите файл, папку или `/` для всего Диска. Кнопка **«Выбрать на Диске…»** позволяет найти файл или папку. Для переноса одного файла укажите полный путь, например `/Проекты/2026/Смета.xlsx`.
3. В поле **«Получатель On-premises»** введите полный email или числовой UID сотрудника и нажмите **«Проверить план»**. Проверка (Dry Run) читает данные обоих Дисков. Дождитесь состояния **«План готов»**. Сверьте получателя, подтверждённый UID, итоговые пути и объём. Уберите галочки с лишних объектов. Галочка папки меняет выбор всех вложенных объектов.
4. **Перед запуском проверьте, что станет публичным в SaaS.** Утилита публикует исходную папку целиком. По ссылке будут доступны и файлы, с которых вы сняли галочки в плане. Для пути `/` публикуются папки верхнего уровня и файлы в корне, из которых требуется перенос. Для полного пути к одному файлу публикуется только этот файл. Ссылки сохраняются после завершения и остановки переноса.
5. Нажмите **«Начать перенос»**. Проверьте, что каждый выбранный файл получил результат **«Перенесено»** или **«Уже совпадает»**. Файл из примера будет у получателя по тому же пути — `/Проекты/2026/Смета.xlsx`. Для пробного переноса откройте его на Диске получателя. Кнопка **«Скачать отчёт CSV»** выгружает результаты. [Журнал и восстановление](#onprem-recovery)

</details>

<details class="help-chapter" id="onprem-shared" markdown="1">
<summary>3. Один источник → общий Диск On-premises</summary>

1. В поле **«Источники»** выберите **«Один диск»**, в поле **«Куда переносим»** — **«Общий диск»**. Заполните **«Доступ к SaaS»** и **«Доступ к On-premises»**. Введите email владельца личного Диска SaaS. Выберите файл, папку или весь Диск (`/`) через **«Выбрать на Диске…»** либо введите **«Исходный путь»** вручную. [Какие доступы нужны](#onprem-requirements)
2. Введите email сотрудника с доступом к общему Диску On-premises и заполните поле **«Метка существующего общего диска»**. Например, для `https://disk.office.example/client/vd/team_42/disk` метка — `team_42`. Нажмите **«Проверить план»**. Дождитесь состояния **«План готов»**.
3. Сверьте сотрудника, метку, объём и итоговые пути. В корне общего Диска утилита создаст папку с email владельца источника. Для `employee@example.org` исходная папка `/Документы` с файлом `report.pdf` даст путь `/employee@example.org/Документы/report.pdf`. Если выбрать источником сам файл `/Документы/report.pdf`, он попадёт в `/employee@example.org/report.pdf`. В плане снимите галочки с ненужных файлов и папок.
4. **Перед запуском проверьте исходный путь.** Если выбрана папка, ссылка в SaaS откроет доступ ко всему её содержимому, включая файлы со снятой галочкой. При выборе `/` утилита публикует нужные папки верхнего уровня и файлы в корне. Для проверки на одном файле задайте его полный исходный путь. Ссылки останутся публичными после завершения и остановки.
5. Нажмите **«Начать перенос»**. Утилита сохраняет имя и структуру исходной папки, в том числе пустые каталоги. В карточке **«Направление»** справа от стрелки сверьте общий Диск и папку получателя. Проверьте результат каждого выбранного файла — **«Перенесено»** или **«Уже совпадает»** — и сохраните его кнопкой **«Скачать отчёт CSV»**. [Журнал и восстановление](#onprem-recovery)

</details>

<details class="help-chapter" id="onprem-personal-list" markdown="1">
<summary>4. CSV → личные Диски сотрудников On-premises</summary>

1. В поле **«Источники»** выберите **«Список дисков из CSV»**, в поле **«Куда переносим»** — **«Личный Диск»**. Заполните **«Доступ к SaaS»** и **«Доступ к On-premises»** один раз для списка. Нажмите **«Скачать шаблон CSV»**. [Какие доступы нужны](#onprem-requirements)
2. Укажите в каждой строке основной email сотрудника SaaS (`source_email`) и полный email получателя On-premises (`destination_email`). В `path` можно указать абсолютный путь к файлу или папке. Пустое поле или `/` означает весь Диск. В `destination_folder` укажите папку, в которой нужно сохранить полный исходный путь. Пустое поле или `/` означает корень Диска получателя.

```csv
source_email,path,destination_email,destination_folder
aivanov@cloud.example,/Документы,apetrov@office.example,/Архив/2026
olga@cloud.example,,osokolova@office.example,
```

3. В первой строке файл `/Документы/Отчёт.xlsx` у `aivanov@cloud.example` попадёт в `/Архив/2026/Документы/Отчёт.xlsx` у `apetrov@office.example`. Во второй строке переносится весь Диск с сохранением путей от корня. Каждый источник должен вести к одному получателю, а у каждого получателя должен быть один источник. Одну пару можно повторить с непересекающимися исходными путями. У каждого переносимого файла должен быть свой итоговый путь. Разные email одного получателя с одинаковым UID считаются одной учётной записью.
4. Сохраните файл в UTF-8 с разделителем-запятой (до 1000 строк данных и 2 МиБ). Выберите его в **«Загрузить CSV»** или вставьте текст с заголовком в **«Список дисков»**. Нажмите **«Проверить план»**. В таблице **«План переноса»** сверьте для каждой пары оба email, подтверждённый UID и итоговый путь.
5. Снимите галочки с лишних пар. Для выбора отдельных объектов раскройте **«Файлы и статус»** → **«Файлы»**. Если у строки ошибка, нажмите **«С ошибками»**, проверьте номер строки и причину. Исправьте доступ и нажмите **«Проверить строку ещё раз»**, исключите строку или поправьте CSV и проверьте новый план. **«Показать все строки»** вернёт полный список.
6. **Перед запуском проверьте `path` каждой выбранной строки.** Ссылка на исходную папку SaaS открывает также вложенные файлы и папки со снятой галочкой. Для всего Диска публикуются нужные папки верхнего уровня и файлы в корне. Для одного файла задайте его полный путь. Ссылки сохраняются после завершения и остановки.
7. Когда планы всех выбранных строк готовы, сверьте число пар и нажмите **«Начать перенос (N)»**. Счётчик учитывает и строки, скрытые фильтром. Откройте **«Файлы»** у каждой пары и проверьте, что выбранные файлы получили **«Перенесено»** или **«Уже есть, MD5 совпадает»**. В разделе **«Сводка, отчёты и история списков»** нажмите **«Скачать план CSV»**. [Журнал и восстановление](#onprem-recovery)

<details markdown="1">
<summary>Короткий CSV, номера строк и повторная проверка плана</summary>

Для целых Дисков и корня назначения достаточно заголовка `source_email,destination_email`. При необходимости добавьте одну или обе колонки путей. Заключайте значения с запятой в двойные кавычки. В каждой строке должны быть все колонки заголовка, в том числе запятая перед пустой последней колонкой.

Первая пара — строка 1. Заголовок и полностью пустые строки в нумерацию не входят. Строка `,,,` содержит четыре пустых поля и вызовет ошибку из-за отсутствующих email. Ошибка формата всего CSV, например неверный заголовок, показывается без номера строки. При конфликте пар план укажет номера конфликтующих строк. Для повторной проверки готового списка нажмите **«Проверить ещё раз»**.

</details>

<details class="help-chapter" id="onprem-shared-list" markdown="1">
<summary>5. CSV → один общий Диск On-premises</summary>

1. В поле **«Источники»** выберите **«Список дисков из CSV»**, в поле **«Куда переносим»** — **«Общий диск»**. Заполните **«Доступ к SaaS»** и **«Доступ к On-premises»**. На весь список укажите метку существующего общего Диска On-premises и email сотрудника с правами чтения и записи на нём. Нажмите **«Скачать шаблон CSV»**. [Какие доступы нужны](#onprem-requirements)
2. Введите один источник на строку. Для личного Диска укажите `personal`, email владельца и оставьте `vd_hash` пустым. Для общего Диска укажите `shared`, email сотрудника SaaS с доступом к нему и метку `vd_hash` из адреса `…/vd/<метка>/disk`. В `path` укажите полный путь к файлу или папке либо `/` для всего Диска.

```csv
type,email,vd_hash,path
personal,employee@example.org,,/
shared,reader@example.org,shared-disk-id,/
```

3. Сохраните CSV в UTF-8 с разделителем-запятой (до 1000 строк данных и 2 МиБ). Выберите файл в **«Загрузить CSV»** или вставьте список с заголовком в **«Список дисков»**. Нажмите **«Dry Run»**. После проверки сверьте метку общего Диска назначения, сотрудника, объём и папку каждого источника. Для личного Диска это `/employee@example.org`, для общего — `/<название> (<ID>)`. Название фиксируется при первом Dry Run.
4. Откройте **«Файлы»** в строке каждого источника, сверьте итоговые пути и снимите галочки с лишних объектов. Чтобы исключить источник целиком, снимите галочку в его строке. При ошибке исправьте причину и нажмите **«Повторить Dry Run»** у этой строки. Запуск доступен только с полными планами всех выбранных источников.
5. **Перед запуском проверьте личные источники.** Ссылка на папку SaaS откроет доступ ко всему её содержимому, включая файлы со снятыми галочками. Для всего личного Диска публикуются нужные папки верхнего уровня и файлы в корне. Для одного файла укажите его полный исходный путь. Ссылки остаются публичными после завершения и остановки. Общие Диски SaaS утилита читает по токену указанного в строке сотрудника, только с временным кешем и без публикации.
6. Нажмите **«Начать перенос»**. В строке источника нажмите **«Файлы»** и проверьте результат каждого выбранного файла — **«Перенесено»** или **«Уже есть, MD5 совпадает»**. В разделе **«Сводка, отчёты и история списков»** нажмите **«Скачать план CSV»**. [Журнал и восстановление](#onprem-recovery)

</details>

<details class="help-chapter" id="onprem-recovery" markdown="1">
<summary>6. Журнал, остановка и восстановление переноса</summary>

| Когда возникла проблема | Что делать |
|---|---|
| До запуска план не готов | При ошибке доступа проверьте поля SaaS и On-premises и исправьте причину. Для одного источника нажмите «Проверить план» или «Составить новый план». В CSV у личной пары нажмите «Проверить строку ещё раз», у источника для общего Диска — «Повторить Dry Run». Проблемную строку можно исключить из плана. |
| Сервер уже принял загрузку, но запрос её статуса временно не проходит и список показывает «Приостановлено» | Дождитесь восстановления связи с Диском назначения. Нажмите **«Продолжить»** у списка. Утилита проверит прежнюю операцию по сохранённому ID без повторной отправки файла. Затем нажмите «Файлы» в строке источника и проверьте результат. |
| У отдельного файла ошибка или «Исход неизвестен» | Посмотрите этап, причину и код в журнале задания. В CSV откройте **«Подробный журнал»** у строки. После устранения причины нажмите **«Проверить и повторить»** у файла, если эта кнопка доступна. [Как проверяется результат повтора](#onprem-retry) |

При включённых автоматических повторах временная недоступность личного Диска затрагивает строку этого получателя. При сбое общего Диска могут приостановиться списки с тем же адресом API и той же меткой назначения. Статус одной строки или одного Диска не означает, что недоступна вся установка. Без автоматических повторов при ошибке передачи утилита пропускает файл и продолжает очередь.

<details id="onprem-journal" markdown="1">
<summary>Прочитать журнал и сохранить результаты</summary>

<a id="подробный-журнал-и-его-выгрузка"></a>

В одиночном задании откройте **«Журнал задания»**, в списке CSV — **«Подробный журнал»** у нужной строки. В журнале найдите **«Ошибка»**, **«Исход неизвестен»** или **«Прервано»** и сопоставьте соседние события по файлу и ID попытки. По стадии видно, где произошёл сбой — при чтении SaaS, публикации, скачивании, создании папки, загрузке в On-premises или проверке результата.

Журнал показывает сторону сбоя, HTTP-статус и код API, если они получены, а также число попыток, паузу, ID операции, время и длительность. Например, **«SaaS: HTTP 500»** означает ошибку на стороне источника. Для сетевого сбоя без ответа сервера HTTP-статуса нет. В журнал и CSV попадают имена и пути файлов. Токены и ссылки доступа из них исключены.

- В одиночном задании **«Скачать отчёт CSV»** выгружает результаты файлов и попыток.
- В списке **«Скачать план CSV»** выгружает строки плана с итогами по объектам.
- **«Скачать журнал CSV»** выгружает события. В одиночном задании в файл попадает вся сохранённая история, на экране видны последние 500 загруженных событий.

В журнале одиночного задания и в журнале списка колонки `publication_attempts` и `max_publication_attempts` показывают номер попытки публикации и её предел. В интерфейсе им соответствует запись «Попытка публикации 3 из 3».

Кодировка CSV — UTF-8 с BOM. Разделитель — запятая, `timestamp_utc` — время UTC, размеры — байты, `duration_ms` — миллисекунды. Для диагностики сохраните план или отчёт вместе с журналом. В одиночном задании ID указан в именах обеих выгрузок и в поле `job_id` журнала. В списке сопоставьте строки двух выгрузок по `source_id`.

Видимый на Диске файл и итог «Завершено с замечаниями» не подтверждают перенос всех выбранных файлов. Успех строки «Каталог» подтверждает только создание папки. «Проверено байтов» увеличивается после проверки результата. «Скачивание в кеш» и «Загрузка на диск» показывают скорость за последние примерно пять секунд.

Выгрузки личного списка содержат номер строки CSV, пару адресов и папку назначения. В отчёте видны подтверждённый UID и итоговые пути файлов.

</details>

<summary>Остановить задание, продолжить его или запустить заново</summary>

| Кнопка | Что делает |
|---|---|
| **Проверить план** (Dry Run) | Проверяет доступ к Дискам и квоту, сравнивает существующие файлы с источником и составляет план в режиме чтения. При входе через сервисное приложение сохраняет UID получателя личного Диска или UID сотрудника с доступом к общему Диску |
| **Составить новый план** | Когда план готов, запускает новую проверку по текущим полям формы. Прежнее задание доступно в истории |
| **Начать перенос** | Запускает готовый план после Dry Run |
| **Пауза** | Приостанавливает очередь новых передач. Утилита продолжает проверять уже принятую операцию до её завершения |
| **Продолжить** | Снимает паузу и обрабатывает оставшиеся файлы плана. После завершения очереди повторяет обычные ошибки. Если список приостановлен во время проверки принятой загрузки, повторно проверяет эту операцию |
| **Остановить полностью…** | Отменяет незавершённые действия **в утилите**, прекращает фоновые проверки и освобождает очередь и пути. Дождитесь «Остановлено полностью». Остановка доступна даже без токенов |
| **Начать заново** | Создаёт новый план для того же источника и назначения. Когда появится «План готов», проверьте пути и нажмите «Начать перенос» |
| **Проверить и повторить** | Проверяет доступ к Диску и состояние целевого файла. Дальнейшие действия зависят от результата [проверки](#onprem-retry) |
| **Очистить временные файлы всех заданий…** | После подтверждения удаляет скачанные временные файлы всех заданий On-premises, включая остановленные и незавершённые. При продолжении нужные файлы скачаются заново. Выполняющийся перенос сначала приостановите или остановите |

**Полная остановка не отменяет принятую сервером операцию:** документированный API On-premises не предоставляет такую команду. Она может продолжаться и расходовать квоту и сеть. Утилита сохраняет её историю, освобождает пути и разрешает новый перенос. Остановленное задание продолжить нельзя — используйте **«Начать заново»**.

Файлы, уже совпадающие по размеру и MD5, получают **«Уже совпадает»**. Несовпадающие файлы остаются **«Конфликтом»**: полная остановка не разрешает их перезаписывать или удалять.

**После перезапуска контейнера** выберите задание в истории и введите Client secret приложения SaaS. Если использовали ADMIN_TOKEN SaaS, введите и его. При входе через сервисное приложение введите Client secret приложения On-premises и токен владельца организации. Если открыли старое задание с готовым токеном сотрудника, введите этот токен и подтвердите его владельца. При необходимости введите ключ режима. Затем нажмите **«Продолжить»**, **«Начать перенос»** для готового плана или **«Начать заново»** для остановленного задания. Доступ проверяется автоматически. Для другого источника или назначения нужен новый план.

Для списка используйте **«Пауза»** или **«Продолжить»** у всего списка. Кнопка **«Остановить весь список…»** запросит подтверждение. После перезапуска выберите список в истории и введите его доступы. Нажмите **«Продолжить»**. Для готового плана, который ещё не запускали, затем нажмите **«Начать перенос»**.

При обновлении старого локального стенда см. [примечание о тестовых заданиях](https://github.com/cromovsky/yandex-disk-copy/blob/v3.3.0/docs/UPDATE.md#old-local-jobs). Их история и выгрузки сохраняются.

Секреты хранятся только в памяти. Ограничьте доступ к хранилищу утилиты, где остаются параметры, пути, попытки и журнал. Держите заполненную форму с токенами в закрытом доступе.

</details>

<details markdown="1">
<summary>Автоматические повторы и проверка результата загрузки в On-premises</summary>

Галочка **«Автоматически повторять при ошибках»** по умолчанию включена.
Её можно менять перед запуском и во время работы, в том числе для всего
списка дисков, без нового Dry Run. Если галочка снята, утилита делает одну попытку. При ошибке она пропускает файл и переходит к следующему. В журнале —
путь, этап, сторона сбоя (SaaS, On-premises или локальный кеш), причина,
HTTP-статус и код API, если сервер их вернул. Утилита отменяет ожидающий повтор. Уже отправленный запрос завершается или дожидается тайм-аута.
Ошибки подготовки доступа и обхода источника показываются отдельно.

Если у файла доступна кнопка **«Проверить и повторить»**, без автоматических повторов одно нажатие запускает одну попытку. Обновление токена после HTTP 401,
пауза после HTTP 429 и проверка уже принятой сервером операции сохраняются.
При повторном включении галочки пропущенные файлы сами не запускаются.

При включённых автоматических повторах для временных сбоев получения ссылки или скачивания предусмотрено **5 попыток всего**. После первой попытки утилита повторяет запрос через **2, 4, 8 и 16 секунд**, плюс случайная задержка до 25 %. Больший `Retry-After` сервера имеет приоритет. После пятой неудачи файл получает **«Ошибка»**, в журнале — **«Пропущен»**. Утилита продолжает обработку остальных файлов. Ошибки авторизации и нехватку места повтор не исправит.

При ошибке связи с On-premises утилита сохраняет готовый кеш и показывает этап сбоя. Если список приостановился во время ожидания принятой загрузки, восстановите связь и нажмите **«Продолжить»** у списка.

Устраните причину и нажмите **«Продолжить»** для нового цикла обычных ошибок. Для отдельного файла с прерванной передачей используйте **«Проверить и повторить»**, если кнопка доступна. Конфликты, изменившиеся исходники и неизвестные исходы кнопка «Продолжить» автоматически не исправляет.

После точечного повтора оставшаяся очередь продолжается автоматически. Если вы сами нажали **«Пауза»**, нажмите **«Продолжить»**. Файлы с неизвестным исходом остаются для отдельной проверки и не мешают обработке оставшегося плана.

</details>

<details id="onprem-retry" markdown="1">
<summary>Повторить перенос одного файла после ошибки</summary>

<a id="onprem-unknown"></a>

1. Откройте одиночное задание или **«Подробный журнал»** строки CSV. Если у файла есть кнопка повтора, нажмите **«Проверить и повторить»**. После перезапуска утилиты сначала заполните доступы. При входе готовым токеном подтвердите его владельца. Для сервисного приложения утилита сверит UID сотрудника с планом.
2. Утилита проверит доступ к выбранному Диску и его корневой папке. Если Диск недоступен, повтор сразу завершится конкретной ошибкой. Файл останется в кеше.
3. Если целевой файл совпадает по размеру и MD5, загрузка не нужна. На общем Диске утилита может отправить файл из проверенного кеша и заменить частичный файл своей прерванной загрузки. На личном Диске другое содержимое означает конфликт.
4. После загрузки утилита проверит размер и MD5 назначения и только затем удалит готовый кеш.

Кнопка также доступна у подходящих файлов с **«Исход неизвестен»**. На личном Диске с сервисным приложением утилита сверяет итоговый файл и, если доступен ID прежней операции, запрашивает её состояние. Если файл отсутствует, повторная отправка из кеша разрешена после подтверждённой ошибки загрузки. При неизвестном результате кеш сохраняется для последующей проверки. Если файл повторяется из проверенного кеша, повторного чтения SaaS не требуется.

Если сохранённый файл кеша утрачен или повреждён, точечный повтор сообщит об этом. После явной очистки кеша через кнопку или при сбое ещё до скачивания утилита получает файл из SaaS заново — для этого нужен доступ к источнику. Ручного ввода ID операции и подтверждения по серверным журналам больше нет.

</details>

<details class="help-chapter" id="onprem-admin" markdown="1">
<summary>7. Как работает перенос и как настроить утилиту</summary>

<details markdown="1">
<summary>Что входит в план и когда его составлять заново</summary>

Dry Run проверяет доступ, квоту и итоговые пути. Утилита читает оба Диска, сравнивает файлы по размеру и MD5. Она ничего не публикует, не скачивает и не записывает на Диск назначения. Проверка в режиме чтения не гарантирует, что позже сервер разрешит публикацию и загрузку. После проверки план зафиксирован, поэтому новые файлы требуют нового Dry Run. Исходники проверяются ещё раз перед отправкой. На время переноса исключите изменения исходников и одновременную запись в целевые пути.

После проверки все объекты выбраны. Галочка папки меняет выбор всего её содержимого, в том числе на других страницах. Выбор вложенного файла включает родительские папки. Исключённые объекты получают «Пропущен пользователем», пропускаются без ошибки и не повторяются. Источник без выбранных объектов также пропускается. Если выбор пуст во всём плане, начать перенос нельзя. Конфликтующий файл можно исключить, чтобы перенести остальные. Выбор сохраняется после перезагрузки страницы и перезапуска контейнера. Менять его можно до первого запуска без нового Dry Run. Если перенос уже запускали или изменили источник, назначение либо параметры плана, составьте новый план.

Если остановили проверку списка, «Dry Run» и «Начать заново» составят новый план. Прежний обход и повторы запросов прекращаются, история сохраняется. Уже отправленный запрос может ждать сетевого тайм-аута. Новый план дождётся свободного места в очереди. Одновременно во всей утилите работают не более четырёх источников, по одному файлу на источник.

При перезагрузке той же вкладки в черновике одиночного задания сохраняются email, исходный путь, получатель, адрес Disk API и идентификаторы организации и приложений. Секреты и токены введите заново. Заголовок «Задание от …» и история показывают время создания плана в часовом поясе браузера. Пауза и продолжение сохраняют эту дату. «Начать заново» создаёт отдельное задание с новой датой.

Для личного Диска сервисное приложение получает временный токен по email или UID. При проверке по email утилита сохраняет `user.uid` ответа Disk API. Если API вернул другой email или не сообщил UID, проверка остановится. Само поле `user.email` необязательно. В API 360 числовому UID соответствует `id` сотрудника. Сохранённые задания по UID продолжают использовать UID. Старое задание с прямым токеном администратора можно продолжить с теми же доступами. [Сведения о Диске](https://yandex.ru/dev/on-premises/disk-api/doc/ru/reference/capacity) · [Карточка сотрудника в API 360](https://yandex.ru/dev/on-premises/api360/doc/ru/ref/UserService/UserService_Get)

</details>

<details markdown="1">
<summary>Как файлы попадают из SaaS в On-premises через локальный кеш и когда создаётся публичная ссылка</summary>

При способе **«С временным сохранением в кэш»** утилита скачивает файл на свою машину, проверяет размер и MD5, загружает в On-premises и проверяет результат. Машине утилиты нужны доступ к обоим сервисам и свободное место.

После проверки перенесённого файла очередь сразу берёт следующий объект.
При отключённых автоматических повторах утилита записывает ошибку в журнал,
пропускает проблемный файл и сразу продолжает перенос. Это действует и для CSV.

Новые задания загружают файлы **сразу под исходными именами**. На общем Диске точечный повтор может заменить частичный файл своей прерванной загрузки. На личном Диске несовпадающий файл остаётся на месте, в журнал попадает конфликт. [Загрузка на личный Диск](https://yandex.ru/dev/on-premises/disk-api/doc/ru/reference/upload)

**Публикация личного источника обязательна** и начинается после **«Начать перенос»**:

- Для исходной папки публикуется сама папка со всем содержимым, включая объекты, с которых сняты галочки. Выбранные файлы скачиваются по одному, без ZIP.
- Для выбранного файла публикуется этот файл.
- Для пути `/` публикуются папки верхнего уровня и отдельные файлы в корне, из которых требуется перенос. Общий Диск SaaS утилита читает с токеном сотрудника без публикации.

При отказе публикации с HTTP 403 или 423 утилита делает до трёх попыток на файл или папку, включая первую. Для этого должна быть включена галочка **«Автоматически повторять при ошибках»**. После третьего отказа в журнале появляется «Пропущен» с кодом ответа SaaS. У папки пропускаются также выбранные файлы и подпапки, которым ещё нужно скачивание по этой ссылке. Остальные объекты и строки CSV продолжают перенос. При выключенных повторах объект пропускается после первого отказа.

**Ссылки остаются публичными после завершения, ошибки и остановки.** Доступ к папке распространяется и на добавленные позже файлы. Существующие пароли и ограничения ссылок сохраняются. Если они мешают скачиванию, причина попадёт в журнал.

Утилита обновляет временный токен по тому же email перед очередным запросом к Disk API. Для часового токена обновление начинается за пять минут до истечения. Если сервер выдал токен на меньший срок, утилита оставляет запас в 10 % срока, максимум пять минут. При каждом обновлении и возобновлении задания она сверяет `user.uid` получателя или сотрудника с доступом к общему Диску с UID в плане. Если UID изменился, перенос на этот Диск останавливается.

</details>

<details markdown="1">
<summary>Включить режим On-premises и настроить доступ к нему по сети</summary>

Готовый образ запускайте по [примеру Docker Compose](https://github.com/cromovsky/yandex-disk-copy/blob/v3.4.0/docs/INSTRUCTION.md#docker-start). Он использует релиз 3.4.0, постоянный том и порт на `127.0.0.1`. Для сборки исходников и локальной HTTP-проверки используйте:

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build -d
```

Откройте `http://localhost:8000`. Override разработки разрешает локальный HTTP через `ONPREM_ALLOW_INSECURE_HTTP=1`. Для готового образа это разрешение уже указано в примере Compose. Если задан `ONPREM_ADMIN_TOKEN`, ключ обязателен и локально.

Используйте HTTP только на локальном стенде. Браузер передаёт утилите токены без шифрования. В `docker-compose.yml` порт по умолчанию опубликован на всех интерфейсах. Для локального доступа задайте `127.0.0.1:8000:8000` либо ограничьте его firewall. API назначения всегда требует HTTPS. Для размещения с Caddy нужны настроенные HTTPS/basic-auth и `ONPREM_ADMIN_TOKEN`. Для запуска версии 3.4.0 с Caddy замените `latest` на `3.4.0` в поле `image` сервиса `disk-copy`. Затем выполните:

```bash
docker compose -f docker-compose.caddy.yml pull
docker compose -f docker-compose.caddy.yml up -d --no-build
```

Для сборки из исходников вместо этих команд используйте `up --build -d`. Не запускайте оба варианта Compose одновременно. В варианте Caddy не открывайте порт приложения наружу и не разрешайте небезопасный HTTP. Клиенты On-premises не используют прокси из окружения: одной переменной `HTTPS_PROXY` недостаточно.

<details markdown="1">
<summary>Задать размер кеша, резерв места и лимиты запросов к On-premises</summary>

| Переменная | По умолчанию / назначение |
|---|---|
| `ONPREM_DATA_DIR` | `/var/lib/disk-copy` в Docker, `./migration-data` без Docker. Содержит базу заданий и подпапку `staging` с кешем. В Docker используется постоянный том `migration-data` |
| `ONPREM_STAGING_MAX_BYTES` | `21474836480` — общий бюджет кеша 20 Гб |
| `ONPREM_STAGING_RESERVE_BYTES` | `1073741824` — резерв свободного места 1 Гб |
| `ONPREM_API_READ_RPS` / `ONPREM_API_WRITE_RPS` | `10` / `2` — темп чтения/изменения API установки |
| `ONPREM_CA_BUNDLE` | Путь к смонтированному PEM-файлу корпоративного CA. По умолчанию используются системные доверенные CA |

Чтобы задать **100 Гб кеша и 2 Гб резерва**, добавьте в `.env` рядом с
`docker-compose.yml` (значения — в байтах):

```env
ONPREM_STAGING_MAX_BYTES=107374182400
ONPREM_STAGING_RESERVE_BYTES=2147483648
```

Остановите активные задания и примените настройки к контейнеру:

```bash
docker compose up -d
```

Для локальной сборки с override разработки сохраните оба файла: `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d`. Для Caddy используйте его файл Compose. Готовый образ не требует override разработки: разрешение локального HTTP задано в его примере Compose.

Compose пересоздаст контейнер на основе готового образа. План и журнал
сохранятся в томе `migration-data`. Введённые в интерфейсе секреты и токены
потребуется ввести заново.

Лимит общий для временных файлов всех заданий. Резерв свободного места учитывается отдельно. Физического места на диске тоже должно хватать.
Нехватка бюджета или места при скачивании вызывает ошибку
`staging_space_insufficient`. Утилита не удаляет старый кеш для освобождения
бюджета автоматически, в том числе при уменьшении лимита.

Для диска объёмом 1 Тб не нужен кеш на весь терабайт: файлы передаются по одному, готовый кеш удаляется после подтверждённого переноса. Для четырёх одновременных источников бюджет должен вмещать **четыре крупнейших одновременно скачиваемых файла и сохранённые остатки других попыток**. Для резерва требуется дополнительное свободное место. Dry Run проверяет этот объём и суммарную квоту назначения. На общем Диске нужна квота для итоговых файлов.

<details markdown="1">
<summary>Очистить кеш и сохранить историю заданий перед обновлением</summary>

Остановка сохраняет кеш и историю. **«Очистить временные файлы всех заданий…»** запрашивает подтверждение и удаляет все файлы из `staging`, в том числе остатки незавершённых попыток и файлы без записи в истории. При продолжении необходимые файлы скачаются заново. История заданий, сведения о серверных операциях, файлы на обоих Дисках и локальные копии в `./downloads` сохраняются.

После старых заданий на Диске могут остаться технические папки `.disk-copy-transfer-<job-id>`. Новые задания обходятся без них. Их можно очистить вручную после подтверждения завершения связанных серверных операций и проверки итогов. Частичные файлы под исходными именами автоматически не удаляются.

Перед пересозданием контейнера сохраните том с журналом восстановления и планами списков (`source-batches.db`). Перед обновлением сделайте согласованную резервную копию базы и кеша при остановленном приложении. Версия 3.4.0 обновляет схему базы On-premises с **9** (3.3.0) до **11**. Для отката нужны предыдущий образ и копия до обновления. Один том поддерживает один процесс приложения. Несколько workers и NFS не поддерживаются.
