# Обновление до 3.2.0

Оба образа поддерживают SaaS → On-premises с временным кешем:

- `cromovsky/yandex-disk-copy-v2:3.2.0` — одна или разные SaaS-организации;
- `cromovsky/yandex-disk-copy:3.2.0` — одна SaaS-организация.

В 3.2.0 после полного Dry Run можно выбрать отдельные файлы и папки
для SaaS → On-premises, включая списки CSV, и локального сохранения по CSV.
По умолчанию выбрано всё. Галочка папки меняет выбор всего её содержимого,
выбор вложенного файла включает нужные родительские папки. Выбор можно менять
до первого запуска без нового Dry Run; он сохраняется после обновления страницы
и перезапуска контейнера. Исключённые объекты не попадают в очередь,
не считаются ошибками и не повторяются. Без выбранных объектов запуск недоступен.

В 3.1.0 во всех режимах и списках CSV добавлена галочка
**«Автоматически повторять при ошибках»**, по умолчанию включённая.
Если её снять, после первой ошибки файл пропускается с записью причины в журнал,
обработка остальных продолжается. Настройку можно менять во время работы
без нового Dry Run; ручной повтор сохраняется.

Выполняйте команды в прежнем каталоге установки с теми же файлами Compose.
Сохраняйте имя проекта: от него зависит имя тома `migration-data`.
Если используете Caddy или override разработки, добавляйте прежние `-f`
ко всем командам Compose ниже.

## Перед обновлением

1. Завершите или полностью остановите активные задания в интерфейсе.
   Остановка утилиты не отменяет уже принятую On-premises операцию;
   проверьте её состояние на стороне назначения.
2. Сохраните `docker-compose*.yml`, `.env`, дополнительные настройки и
   подключения сертификатов. Сохраните каталог `downloads` на машине запуска.
3. Остановите приложение и скопируйте постоянные данные, включая кеш:

   ```bash
   docker compose stop disk-copy
   docker cp "$(docker compose ps -aq disk-copy):/var/lib/disk-copy" \
     "./backup-migration-data-$(date -u +%Y%m%dT%H%M%SZ)"
   ```

   Проверьте, что резервная копия содержит базы и каталог `staging`.
   Не запускайте приложение до завершения копирования.

Не удаляйте `downloads` и том `migration-data`. Команда `docker compose down -v`
удаляет историю, планы и кеш. Для отката сохраните прежний образ и копию данных
до обновления: текущая схема базы On-premises — **9**. Обновление добавляет
сохранение выбора файлов и папок; прежние планы получают выбор всех объектов.

## Если используется готовый образ

В существующем Compose замените тег `image` на `3.2.0`, сохранив остальные
настройки и тома. Затем:

```bash
docker compose pull
docker compose up -d --no-build
```

Для перехода с локальной сборки на готовый образ замените `build: .` на
`image: cromovsky/yandex-disk-copy-v2:3.2.0` в прежнем Compose.
Для варианта v1 укажите `cromovsky/yandex-disk-copy:3.2.0`.
Сохраните все остальные параметры, включая `container_name`, DNS, порты,
`environment` и `volumes`. Запускайте готовый образ без override разработки.
Если нужен доступ через `http://localhost:8000`, перенесите разрешение
`ONPREM_ALLOW_INSECURE_HTTP: "1"` в `environment` основного файла и ограничьте
порт `127.0.0.1:8000:8000`. Для доступа через HTTPS с Caddy нужны
`ONPREM_ADMIN_TOKEN`, TLS и авторизация; разрешение HTTP не включайте.
Полный пример готового Compose — [в инструкции](INSTRUCTION.md#docker-start).

Compose читает `.env` для подстановок `${...}`. Сохраняйте такие подстановки
при переходе на готовый образ: одного файла `.env` недостаточно, чтобы передать
в контейнер параметры кеша, лимиты и ключ режима. Корпоративный CA также
должен остаться смонтирован в контейнер.

## Если используется сборка из исходников

Обновите исходники и пересоберите образ:

```bash
git pull --ff-only
docker compose up --build -d
```

Для локального HTTP-стенда, использующего override разработки:

```bash
git pull --ff-only
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build -d
```

Если в исходниках есть свои изменения и `git pull --ff-only` не проходит,
сначала сохраните и согласуйте их с новой версией. Команда `pull` готового
образа не обновляет сборку, заданную через `build`.

## После запуска

```bash
docker compose ps
docker compose logs --tail=100 disk-copy
```

Откройте утилиту и обновите страницу. Проверьте доступность режима
SaaS → On-premises, выбор файлов и папок в готовом плане,
галочку **«Автоматически повторять при ошибках»**, историю и CSV,
каталог локальных копий. Для продолжения
задания или списка введите Client secret и использованные токены заново;
подтвердите владельца токена назначения. Секреты хранятся только в памяти.
Незавершённые SaaS-переносы и одиночные локальные сохранения после перезапуска
помечаются как прерванные и автоматически не повторяются.

### Старые локальные тестовые задания

Тестовые задания с прежним способом передачи остаются в истории, но не
запускаются, не продолжаются и не повторяются (`onprem_staged_required`).
Сохраните их CSV и создайте новый Dry Run с временным кешем.
История, выгрузки и полная остановка доступны; уже принятую сервером операцию
проверяйте на стороне On-premises.
