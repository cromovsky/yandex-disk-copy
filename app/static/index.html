Скачать шаблон

Заполните скачанный шаблон и загрузите его кнопкой-скрепкой. Формат: SOURCE;DESTINATION, одна пара на строку. Не больше 25 пар; одновременно идут 5 переносов.

Список пока пуст

Все источники из списка переносятся на этот общий диск от имени указанного сотрудника.

Откройте общий диск в браузере — в URL будет .../vd/<метка>/.... Можно вставить метку или весь URL.

На личный Диск файлы сохраняются в папку по email источника с оригинальными именами. На общий диск — в папку с тем же именем на выбранном общем диске (нужны метка vd_hash и сотрудник с правом записи). Для пакетного переноса откройте вкладку «Несколько дисков»: до 25 источников, по 5 переносов одновременно. Если сотрудник-источник заблокирован, он временно разблокируется на время переноса и блокируется обратно.

Организация источника

Что сохраняем

Откройте общий диск в браузере: в адресе будет .../vd/<метка>/.... Вставьте метку или весь URL. В SOURCE укажите email сотрудника с доступом к этому диску.

Путь внутри выбранного диска. / сохраняет весь диск.

Дополнительные настройки

Число элементов в одном запросе при обходе папок. Все файлы сохраняются независимо от размера страницы.

Файлы сохраняются на машине, где запущена утилита. Личный Диск — в ./downloads/<email>, общий диск — в ./downloads/shared/<метка>. В стандартном Docker Compose это папка downloads проекта на машине запуска. Если сотрудник-источник заблокирован, утилита временно разблокирует его и вернёт блокировку после завершения.

Пилотный режим. Совместимость и безопасная финализация должны быть подтверждены на стенде.

Токены, права и доступы

      
SaaS → On-premises

      
Для источника нужны ID SaaS-организации, Client ID и Client secret
         зарегистрированного сервисного приложения с правом
         cloud_api:disk.read, а также email сотрудника.
         Для назначения нужны HTTPS-адрес API установки и
         пользовательский OAuth-токен получателя из паспорта on-premises.
         Админ-токен API 360 и SCIM-токен здесь не используются.

      
Где получить каждый доступ, как заполнить форму и выполнить перенос:
         вкладка «Инструкция», раздел
         «SaaS → On-premises: инструкция миграции».

      
Перенос между SaaS-Дисками

      
Для этих режимов нужны два независимых набора данных:
         сервисное приложение (доступ к Дискам сотрудников) и
         админ-токен API 360 (временная разблокировка
         сотрудника-источника). Их получают разные роли.

      
Здесь доступны «Одна организация» —
         источник и получатель в одной орге, один сервис-аккаунт на обоих; и
         «Между организациями» — источник и получатель в разных
         оргах, тогда нужен свой сервис-аккаунт в каждой
         (см. раздел «Режим „Между организациями“» ниже).

Откройте главную вкладку «Сохранить локально».

Набор 1. Сервисное приложение — доступ к Дискам
        владелец организации

      
Сервисное приложение позволяет выпускать временный токен от имени любого
         сотрудника организации по его email (механизм token-exchange). Токен живёт
         один час — инструмент обновляет его автоматически. Все шаги ниже
         выполняются под учётной записью владельца организации.


      
Шаг 1. Войдите в аккаунт владельца организации
         (именно владельца, не администратора).


      
Шаг 2. Убедитесь, что в организации настроен
         почтовый домен — без него сервисные приложения не работают.


      
Шаг 3. Создайте основное OAuth-приложение для
         управления списком сервисных приложений на сайте
         https://oauth.yandex.ru и выдайте ему права:

      
    
        
  • ya360_security:service_applications_read
            — чтение списка сервисных приложений;
    • 
        
  • ya360_security:service_applications_write
            — управление списком (чтение и запись).
    • 
      

      
Получите OAuth-токен владельца для этого приложения — им авторизуются
         запросы из шагов 5–7.


      
Шаг 4. Создайте отдельное
         OAuth-приложение для доступа к Дискам и выдайте ему права:

      
    
        
  • cloud_api:disk.read — чтение Диска;
    • 
        
  • cloud_api:disk.write — запись на Диск
            назначения;
    • 
        
  • cloud_api:disk.info — информация о
            свободном месте.
    • 
      

      
После создания скопируйте его ClientID и
         Client secret — это значения CLIENT_ID и
         CLIENT_SECRET в форме.


      
Шаг 5. Включите функцию сервисных приложений
         (если ещё не включена). Запрос с заголовком
         Authorization: OAuth <токен владельца>:

      
POST https://api360.yandex.net/security/v1/org/<ORGID>/service_applications/activate


      
Шаг 6. Зарегистрируйте приложение из шага 4 как
         сервисное для организации:

      
POST заменяет весь список сервисных приложений.
         Сначала получите текущий список запросом GET из шага 7, сохраните
         прежние записи и добавьте новое приложение. Пример ниже подходит
         только для пустого списка; иначе передайте все записи с их правами.
         Описание замены списка.

      
POST https://api360.yandex.net/security/v1/org/<ORGID>/service_applications

      
Тело запроса (поле id — это ClientID из шага 4):

      
{
  "applications": [
    {
      "id": "<CLIENT_ID>",
      "scopes": [
        "cloud_api:disk.read",
        "cloud_api:disk.write",
        "cloud_api:disk.info"
      ]
    }
  ]
}


      
Шаг 7. Проверьте, что приложение в списке — тем же
         токеном владельца:

      
GET https://api360.yandex.net/security/v1/org/<ORGID>/service_applications

      
Без шагов 5–7 token-exchange возвращает
         400 invalid_request / Unauthorized.

Набор 2. Админ-токен API 360 — блокировка / разблокировка
        администратор организации

      
У заблокированного сотрудника нельзя выпустить токен Диска. Поэтому если
         источник заблокирован, инструмент через API 360 временно разблокирует
         его на время копирования и вернёт блокировку в конце (даже при ошибке).
         Для этого нужен отдельный OAuth-токен с правом управления сотрудниками.


      
Шаг 1. Зарегистрируйте отдельное
         OAuth-приложение на https://oauth.yandex.ru и
         выдайте ему права:

      
    
        
  • directory:read_users — чтение данных и
            проверка статуса сотрудника;
    • 
        
  • directory:write_users — блокировка и
            разблокировка сотрудника.
    • 
      


      
Шаг 2. Под учётной записью администратора
         организации откройте в браузере ссылку (подставьте ClientID этого
         приложения):

      
https://oauth.yandex.ru/authorize?response_type=token&client_id=<ClientID>


      
Шаг 3. Скопируйте выданный токен из адресной
         строки — это значение ADMIN_TOKEN в форме. При изменении прав
         приложения токен нужно выпустить заново (старый сохраняет прежний набор
         прав).

        https://yandex.ru/dev/api360/doc/ru/access
        открыть ↗


      
ORGID, SOURCE и DESTINATION

      
    
        
  • ORGID — числовой идентификатор организации. Виден в админке
            Яндекс 360 или через API 360:
            GET https://api360.yandex.net/directory/v1/org
    • 
        
  • SOURCE — email сотрудника, с Диска которого копируем.
    • 
        
  • DESTINATION — email сотрудника, на Диск которого копируем.
    • 
      


      
Режим «Между организациями»
        сервис-аккаунт в каждой орге

      
Сервисное приложение выпускает токены только для сотрудников своей
         организации, поэтому для переноса между разными оргами «Набор 1»
         настраивается дважды — отдельно в орге-источнике и в
         орге-получателе (у каждой свои CLIENT_ID/CLIENT_SECRET,
         зарегистрированные как сервисные по шагам выше). На вкладке «Между
         организациями» поля разложены по двум блокам:

      
    
        
  • Источник (организация 1): CLIENT_ID,
            CLIENT_SECRET, ORGID, ADMIN_TOKEN,
            SOURCE.
    • 
        
  • Получатель (организация 2): CLIENT_ID,
            CLIENT_SECRET, DESTINATION. Здесь
            ADMIN_TOKEN и ORGID не нужны — блокировкой
            управляем только на стороне источника, получатель считается активным.
    • 
      


      
Важное

      
    
        
  • Одна или разные организации. В режиме «Одна
            организация» источник и получатель обязаны быть в одной орге (один
            сервис-аккаунт на обоих). Для разных орг — режим «Между организациями»:
            token-exchange не пересекает границы организации, поэтому в каждой
            орге нужен свой сервис-аккаунт (в орге-источнике ещё и
            ADMIN_TOKEN для разблокировки).
    • 
        
  • Временный токен сотрудника действует один час; инструмент обновляет его
            автоматически, если копирование идёт дольше.
    • 
        
  • Файлы попадут в отдельную папку на Диске получателя
            (названа по email источника, напр. disk:/user@company1.ru)
            с оригинальными именами.
    • 
        
  • Принцип наименьших привилегий: не используйте персональный токен
            владельца с полным доступом — только перечисленные выше права.
    •

⚠️ Важно: статус инструмента и ответственность

      
Это не готовое продуктовое решение Яндекса и не часть
         официальной поставки Яндекс 360. Инструмент предоставляется «как есть»
         (as is) — вспомогательный материал для администраторов, которые
         самостоятельно решают задачу переноса файлов между Дисками сотрудников.

      
Использование — на свой страх и риск. Все риски, связанные
         с запуском, настройкой и эксплуатацией (в том числе потеря или дублирование
         файлов, простой Диска, нарушение внутренних политик безопасности,
         некорректная работа при изменении API или лимитов) несёт
         организация, выполняющая перенос.

      
Перед боевым запуском:

      
    
        
  • протестируйте на одной паре сотрудников и небольшой папке;
    • 
        
  • согласуйте использование сервисных приложений с политиками ИБ и
            юридической службой;
    • 
        
  • убедитесь, что получено необходимое согласие пользователей на доступ к
            их Диску.
    • 
      

      
Официальная поддержка Яндекс 360 не распространяется на
         этот инструмент.
